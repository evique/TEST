# Политика безопасности системы 

## 1. Защита от SQL-инъекций

**Описание уязвимости:** 
SQL-инъекция возникает, когда данные пользователя (например, логин) конкатенируются со строкой SQL-запроса. Пример атаки: ввод строки `' OR '1'='1` в поле логина превращает запрос `SELECT ... WHERE login = '{login}'` в `SELECT ... WHERE login = '' OR '1'='1'`, что заставляет базу вернуть всех пользователей.

**Решение:** 
Полный отказ от f-строк в SQL-запросах. Использование параметризованных запросов через `?` и кортежи аргументов. База данных воспринимает вредоносную строку как литерал, а не как часть команды.

**Пример безопасного кода:**

cursor.execute("SELECT * FROM users WHERE login = ?", (login,))

## 2. Хранение паролей

Политика: Пароли никогда не хранятся в открытом виде. В таблице users добавлено поле password_hash (TEXT). Используется односторонний алгоритм хэширования SHA-256 (модуль hashlib). При входе введенный пароль хэшируется и сравнивается с сохраненным хэшем.

## 3. Разграничение прав

Политика минимальных привилегий:

admin_db: Полный доступ (SELECT, INSERT, UPDATE, DELETE, CREATE, DROP). Используется только для инициализации БД.
developer: Изменение данных (SELECT, INSERT, UPDATE).
reader: Только чтение (SELECT). Приложение подключается к БД с правами, необходимыми для текущей операции, избегая использования суперпользователя.

## 4. Аудит доступа

Описание: Все попытки входа в систему (успешные и неудачные) фиксируются в таблице login_audit (поля: login, status, login_time). Это позволяет отслеживать попытки подбора паролей (brute-force) и несанкционированный доступ.

## 5. Защита файла базы данных

Рекомендации: Так как SQLite — это файл shoe_store.sqlite, защита на уровне СУБД отсутствует. Безопасность обеспечивается на уровне ОС:

Linux/macOS: Установить права chmod 600 db/shoe_store.sqlite (только владелец может читать и писать).
Windows: Ограничить доступ к папке db/ через ACL (только для учетной записи, под которой запущен сервис).
