## Отчет по практике: Администрирование базы данных SQLite (День 12)

## 1. Как в SQLite реализуются роли и права (на уровне приложения)

Разграничение доступа реализовано программно на уровне Python-приложения:

В базе данных создана таблица roles (содержит id, name, description) и поле role_id в таблице users.
При входе пользователя в систему приложение выполняет SQL-запрос SELECT r.name FROM users u JOIN roles r ON u.role_id = r.id WHERE u.id = ?, чтобы определить текстовое имя роли (например, reader).
Доступ к операциям разрешается не базой, а словарем PERMISSIONS в коде. Если запрашиваемое действие (например, DELETE) отсутствует в списке разрешенных для данной роли, Python-код блокирует выполнение запроса и не отправляет его в SQLite.

def check_permission(conn, user_id, action):
    cursor = conn.cursor()
    cursor.execute("SELECT r.name FROM users u JOIN roles r ON u.role_id = r.id WHERE u.id = ?", (user_id,))
    result = cursor.fetchone()
    
    if not result:
        return False
        
    role_name = result[0]
    allowed_actions = PERMISSIONS.get(role_name, [])
    return action.upper() in allowed_actions

## 3. Способы резервного копирования

- В ходе работы были реализованы два метода создания бэкапов:

Способ	Плюсы	Минусы
shutil.copy() (Задание 2.1)	Максимальная простота реализации; не требует открытия второго соединения с БД.	Небезопасен при «горячем» копировании. Если в момент копирования приложение записывает данные, итоговый файл может оказаться поврежденным («битым»).
conn.backup() (Задание 2.2)	Безопасный способ. Создает консистентный (целостный) снимок базы. Метод корректно работает даже если в основную БД в этот момент идут транзакции на запись.	Требует написания чуть большего объема кода (открытие второго соединения).

Вывод: Для автоматизированных скриптов обслуживания следует использовать conn.backup().

## 5. Пошаговый сценарий восстановления базы из бэкапа

Создание бэкапа: Был выполнен вызов функции backup_simple(). Файл сохранен по пути db/backups/backup_2026_10_29_14_30.sqlite.
Симуляция сбоя: База данных db/shoe_store.sqlite была открыта в утилите DB Browser for SQLite. Из таблицы orders были безвозвратно удалены все строки (очистка таблицы).
Остановка: Работающее Python-приложение было закрыто, чтобы освободить файл БД.
Восстановление: Запущена функция restore(<путь_к_бэкапу>, 'db/shoe_store.sqlite'). Файл бэкапа был скопирован поверх поврежденной базы с помощью shutil.copy2.
Проверка: Приложение запущено повторно. При просмотре таблицы orders через SQLite Viewer подтверждено, что все удаленные заказы вернулись на свои места. Целостность данных полностью восстановлена.
