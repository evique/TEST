## Функциональные требования: ##
1) В каталоге должно храниться актуальное доступное для заказа количество
товарных позиций, то есть сочетаний модели и размера.
2) Для каждой модели в каталоге должно сохраняться изображение.
3) Пользователь должен иметь возможность выбрать из каталога одну или
несколько пар обуви доступного размера, модели.
4) В интерфейсе должен быть доступен просмотр списка заказов с
отображением ключевой информации: дата заказа, ФИО клиента
5) Должно быть реализовано управление заказами.

## Роли пользователей и их права:
1) Неавторизованный пользователь должен иметь возможность просматривать
каталог товаров (допустимо без фильтрации, сортировки, поиска).
2) Авторизованный пользователь должен иметь возможность просматривать
каталог товаров (с фильтрацией, сортировкой и поиском), оформлять заказы:
добавлять/удалять товарные позиции, изменять количество.
3) Менеджер должен иметь возможность просматривать каталог товаров (с
фильтрацией, сортировкой, поиском), оформлять заказы (добавлять/удалять товарные
позиции, изменять количество), просматривать заказы, состав конкретного заказа,
добавлять новые заказы и удалять существующие.
4) Администратор должен иметь возможность просматривать каталог товаров (с
фильтрацией, сортировкой, поиском), оформлять заказы (добавлять/удалять товарные
позиции, изменять количество), просматривать заказы, состав конкретного заказа,
добавлять новые заказы и удалять существующие. Администратор должен иметь
возможность редактировать заказ.

## Отличие пользователей при ввходе:
Вход в систему осуществляется по уникальному логину без ввода пароля. Поле `login` в таблице пользователей имеет ограничение `UNIQUE` для предотвращения дублирования учетных записей.

## Сущности и атрибуты
* Roles (Роли): `role_id` (PK), `role_name` (UNIQUE).
* Users (Пользователи): `user_id` (PK), `login` (UNIQUE, NOT NULL), `last_name` (NOT NULL), `first_name` (NOT NULL), `middle_name`, `role_id` (FK).
* Products (Товары): `product_id` (PK), `category` (NOT NULL), `sub_category`, `manufacturer` (NOT NULL), `name` (NOT NULL), `image_path`, `composition`, `description`, `price` (NOT NULL).
* Sizes (Размеры): `size_id` (PK), `size_value` (NOT NULL, UNIQUE).
* StockItems (Товарные позиции): `stock_item_id` (PK), `product_id` (FK), `size_id` (FK), `quantity` (NOT NULL, DEFAULT 0).
* Orders (Заказы): `order_id` (PK), `order_date` (NOT NULL, DEFAULT CURRENT_TIMESTAMP), `user_id` (FK).
* OrderItems (Состав заказа): `order_item_id` (PK), `order_id` (FK), `stock_item_id` (FK), `quantity` (NOT NULL), `unit_price` (NOT NULL).

## Связи между сущностями
* `Roles` 1 : N `Users` (одна роль назначается многим пользователям).
* `Users` 1 : N `Orders` (один пользователь может оформить много заказов).
* `Products` 1 : N `StockItems` (товар имеет много позиций по размерам).
* `Sizes` 1 : N `StockItems` (размер входит во многие товарные позиции).
* `Orders` 1 : N `OrderItems` (заказ содержит много позиций).
* `StockItems` 1 : N `OrderItems` (товарная позиция может входить в разные заказы).
